# ProxyMind: handoff for a new working session

Read this first, then `CLAUDE.md` (rules), `docs/plan.md` (roadmap) and `docs/adr/` (decisions). Everything below reflects `main` plus the XSS-proof work (reflection oracle).

## 1. What ProxyMind is

An open-source, AI-native intercepting proxy for authorized web security testing: one workspace where humans and AI agents (over MCP or the built-in assistant) work on the same project, under a policy gate that enforces the rules of engagement. Its differences: any model including local ones, **no proof, no finding** (the tool verifies findings itself), a live app model with multi-identity authorization testing, a hypothesis ledger and coverage map, and open benchmarks.

- Repo: `ommirkute/ProxyMind`, default branch `main`. Licence AGPL-3.0 core (ADR-0007).
- Rust workspace (edition 2024, MSRV 1.88, `unsafe` forbidden, line width 120) plus a React + TypeScript web UI in `ui/`, built into the binary.
- One binary: `proxymind` (crate `pm-cli`).

## 2. Architecture

```
            browser / device                AI agent (Claude Code, …)       web UI (React)
                   │                                 │ MCP (stdio)               │ REST + SSE
                   ▼                                 ▼                           ▼
  ┌──────────── pm-proxy ───────────┐          pm-mcp ──┐      pm-assistant ─┐   pm-api
  │ CONNECT / TLS MITM (pm-tls)     │                   │   (agent:assistant)│     │
  │ HTTP/1.1 (pm-http, byte-exact)  │                   ▼                    ▼     ▼
  │ HTTP/2 (h2) · WebSockets        │            ┌──────────── pm-service ────────────┐
  │ intercept queue · match/replace │◄──hooks────│ the ONLY entry point for actions   │
  │ transparent mode · loop guard   │            │ every send → pm-policy gate        │
  └──────────────┬──────────────────┘            │ (scope, tiers, approvals, rate     │
                 │ Recorder (single writer)      │  limits, DNS check, audit chain)   │
                 ▼                               └──┬───────────┬──────────┬──────────┘
            pm-store (SQLite project file, blobs)    │           │          │
                                                 pm-replay   pm-identity  pm-model / pm-ledger
                                                 (send engine, pm-diff     pm-proof / pm-oast / pm-browser
                                                  HTTP/2, race, pm-ai (views, redaction,
                                                  upstream proxy) untrusted tagging)
```

Rules that shape everything (ADR-0005, CLAUDE.md):
- **One service layer.** API, MCP, CLI, UI and the assistant all call `pm-service`; every action that touches a target goes through `pm-policy`. Lower crates never import higher ones.
- **Byte-exact traffic** (ADR-0002). `pm-http` is sans-I/O and never rewrites bytes; the only automatic change is absolute-form → origin-form targets. Any other change happens only because the user asked (rules, intercept edits, WebSocket intercept stripping compression).
- **Target content is untrusted**, including when shown to a model (wrapped in `<untrusted_target_content>`, prompt-injection signals flagged).
- **Migrations in `pm-store` are append-only.**

### Request paths

- **Browser traffic:** `pm-proxy` reads a request → match/replace rules → intercept queue (humans only) → `Sender` (`pm-replay`) → response → rules/intercept for the response → back to the client; the `Recorder` (single writer thread) stores the exchange. WebSocket upgrades are relayed byte for byte with a decoded copy logged, or message-by-message when WebSocket interception was on at upgrade time.
- **Agent / API / assistant action:** `pm-service` builds an `Outgoing` → `gate_send_with()` asks `pm-policy` (scope + tier + window + approval) → rate-limit slot → secrets un-redacted, identity applied → `Sender` with a DNS check (`policy.check_resolved`) → exchange recorded with the actor's id → a redacted, token-budgeted view goes back.
- **Approvals:** a gated action returns `pending_approval` with an id; a human approves (UI/CLI); the agent repeats the call with identical arguments plus `approval_id`. The approval is bound to a hash of the parameters and is single-use.

ReDoS: as the owner, each JSON string field gets `a×16/22/26 + !`; a hit needs ≥1.5 s at 26, ≥8× the 16-character time, and a slow repeat. Cross-user writes: unique marker values, refused anonymously (401/403), sent as another user; a 2xx is a lead unless reading the object back as its owner shows a written field without the marker (the write went to the caller's own account: VAmPI's email). Fields reads never show (passwords) stay unverified leads. VAmPI 8/8. Test: `crates/pm-service/tests/write_checks.rs`.
- **Replay groups** (`pm-service/src/group.rs`, `POST /api/v1/replay/group`, MCP `replay_group`, SDK `replay_group`/`replayGroup`, Replay "Send group…"): 2–20 different requests (tabs) to one server, `sequence` (one after another, optional `stop_on_error`; each goes through `send_as`, so identities re-login) or `parallel` (`Sender::send_race` with the different requests: HTTP/2 single packet or last-byte sync; at least active-intrusive). One gate decision covers the group and the approval binds every request in order; a group must stay on one server because the rules of engagement decide per target, and every request is scope-checked. Test: `crates/pm-service/tests/race.rs` (sequence 200→409, parallel redemptions win more than once, limits, agent approval).
- **Response-modification presets, Copy as code, Render view** (`pm_proxy::presets`, `pm_tools::codegen`, `/api/v1/match-replace/presets`, `/exchanges/{id}/code?lang=python|javascript|powershell`, `/tools/code`; Match & replace "Add a preset…", History right-click "Copy as …", Replay "Request…" menu, a Render button on HTML responses). Presets are ordinary regex rules a person adds and can edit: unhide hidden fields, enable disabled/readonly fields, remove maxlength, form `novalidate` and no `onsubmit`, remove `<script>` elements, drop CSP/X-Frame-Options/HSTS, remove the cookie Secure/HttpOnly flags; body presets also remove `Accept-Encoding` (in scope) so responses arrive uncompressed. One pass changes each matching tag once. Snippets skip framing headers and a Host matching the URL, join repeated headers, don't follow redirects, and write binary bodies as hex. Render shows decoded HTML in a `sandbox=""` srcdoc iframe behind a `default-src 'none'` CSP meta, so the page runs no scripts and fetches nothing.
- **Web UI look** (`ui/src/styles.css` tokens, `icons.tsx`, `palette.tsx`): a left sidebar of sections with inline SVG icons (collapsible, `pm-sidebar-collapsed`), a header with the group's sub-pages as segmented tabs, the scope pill, live counter and a Ctrl+K / ⌘K command palette; light and dark themes follow the system or the sidebar switch (`pm-theme`, `html[data-theme]`). - **Web UI** (`ui/src`): sections (`App.tsx` GROUPS): Dashboard (Overview, Search, Findings, Scanner issues, Approvals, Audit log), Target (Site map & Search, Model & Coverage, Engagement tools, Scope & rules), Proxy (Intercept, HTTP history with sortable columns, scope/status/extension filters, highlights and comments, right-click menu, Ctrl+R/Ctrl+I; WebSockets history; Match & replace; Proxy setup), Fuzzer (attacks run in the background via `POST /api/v1/fuzzer/attacks`, polled with `?from=`, pause/resume/cancel; payload types list/numbers/brute forcer/null/case variants/built-in; processing rules; grep (text or regex) and extract columns; concurrency and throttle; Auto-mark; sortable, filterable results with a detail pane and Send to Replay; up to 10 000 requests), Collaborator, Organizer, Replay ("Request…" menu: change method, body encoding; named tabs saved in the project via `/api/v1/ui/replay`, per-tab send history with ‹ ›, Ctrl+Enter, an Inspector that edits query/body/JSON parameters, cookies and headers in place, follow redirects, Paste cURL, Race), Authz, Tools (Codec, Diff, Token analyzer), Assistant, Settings (Network). ## 3. What's done

All of this has automated tests and passes CI on Linux, macOS and Windows plus a Chromium end-to-end test.

- **Proxy:** HTTP/1.1 (byte-exact), HTTP/2 to browsers and servers with downgrade (ADR-0009: HTTP/2 shown as text with `HTTP/2` in the request line), CONNECT + TLS interception, transparent mode (Host routing, TLS without CONNECT via SNI, loop guard), upstream HTTP/SOCKS5 proxy and per-host client certificates. Extra listeners from the project (`pm_proxy::Listeners`, setting `proxy_listeners`, `/api/v1/proxy/listeners`; started and stopped live, optional redirect of everything to one host with force-TLS), hostname overrides (`NetConfig.hosts`, used by every sender instead of DNS; TLS keeps the name) and TLS pass-through hosts (`NetConfig.tls_passthrough`; CONNECT and SNI-routed TLS are tunnelled untouched and unrecorded, SNI read with `pm_tls::peek_client_hello`).
- **Active scanner, step 1** (`pm_scan::active`, `Service::scan_active`; matrix and plan in `docs/scanner-matrix.md`): insertion points now include cookies and the User-Agent, Referer and X-Forwarded-For headers. One-shot checks run first (`sql_error` is confirmed by re-sending the probe and the clean request; `cmd_injection` needs the shell to compute `$((7*191))`; eight template-engine syntaxes), then multi-step ones: `sql_boolean` (true/false pairs in four quoting contexts, content similarity against the page's own noise, a second formulation must agree), `sql_time` and `cmd_time` (sleep 3 slow, sleep 0 fast, sleep 5 slower; skipped when the baseline is slow). One gate decision covers the upper bound of requests; default budget 300. VulnShop's VS-3 runs a real SQLite query with `SLEEP()`.
- **Active scanner, step 2: out of band** (`pm_scan::oob`): with an OAST listener (`oast_public_url`, optional DNS zone), `scan_active` sends `ssrf_oob`, `xxe_oob`, `sql_oob`, `cmd_oob`, `ssti_oob`, `log4shell`, `code_oob` probes right after the one-shot checks, each with its own token; callbacks are matched after the slower checks (`oob_wait_seconds`, default 10). DNS-only payloads (nslookup, UNC, JNDI) need the DNS zone. VulnShop: the simulated shell's curl/wget really fetch, and VS-16 is a blind XXE in `POST /api/import`. `bench/run.sh` starts an OAST listener on docker0 (reachable from containers). Watch out: two `self.store.lock()` in one struct literal deadlock (both guards live to the end of the statement).
- **Active scanner, step 3a:** `sql_error` probes also send `*)(` and `']` and report `nosql_error`, `ldap_error` or `xpath_error` by error signature (`injection_error`); `crlf` (header added via CR LF), `host_header` and `cors` (request-level probes: `request_probes`, `set_header`), and multi-step `nosql_operator` (plain vs `$eq` vs `$ne`, confirmed with `$regex`; `name[$ne]=` in query/form, objects in JSON), `auth_bypass` (only on a 401/403 baseline; 8 path tricks plus X-Original-URL/X-Rewrite-URL/X-Forwarded-For…, each checked against the same trick on a missing path) and `hidden_params` (70 names in one request; reflection, or a difference beyond the page's noise bisected to one name). VulnShop VS-17…VS-22 cover them; `/out` now rejects control characters (the scanner found it header-injectable).
- **Active scanner, step 3b:** `stored_xss` (submissions only: each Query/Form/JSON point gets a unique `<marker>s<i><pmx>"'`, then up to 8 recent same-origin HTML GETs from history, not the scanner's own, are re-fetched and checked for the unencoded value), `dom_xss` (GET pages with an HTML baseline and a Chromium: same-origin scripts are fetched once through the gate and served as `pm_browser::Resource`s; each query value and the URL fragment carry `<marker><pmx>'"`; `RenderOptions.init_script` = `dom_hooks`, which wraps innerHTML/outerHTML/srcdoc/insertAdjacentHTML/document.write/eval/setTimeout/Function/location… and reports through the `pmProof` binding; `dom_dangerous` decides) and `csrf` (state-changing requests with a cookie, no Authorization and no token-like name: same request with a foreign Origin/Referer, plus text/plain for JSON; accepted = same 2xx/3xx status and similar body). New insertion points: parameter names (`name_points`; quote and reflection probes only), JSON or base64 inside query/form/cookie values (`PointKind::Nested`, e.g. `ctx.category (base64)`; re-encoded the same way) and XML element text (`PointKind::Xml`). Cookie payloads are no longer percent-encoded except for separators. Crawl and audit (`pm-service/src/scan_task.rs`, `/api/v1/scan/tasks`, Issues page): one background task crawls the start URL, then scans the origin's operations (`scan_targets`, shared with the auto sweep; submissions get only stored_xss/csrf), with progress, cancel, and strong issues recorded as suspected findings (`record_scan_leads`). The auto sweep now also sends recorded submissions (stored_xss, csrf; up to 10, not logins). VulnShop VS-23 stored XSS (`/api/guestbook` → `/guestbook`), VS-24 CSRF (`/api/profile`), VS-25 DOM XSS (`/welcome` + `/static/welcome.js`), VS-26 SQLi in base64 JSON (`/api/recommend?ctx=`); traps `POST /api/settings` (checks Origin) and `/hello` (textContent).
- **Active scanner, step 4a** (`pm_scan::advanced`, plans in `scan.rs`): `jwt` (tokens found in the *unredacted* request, since the redactor hides them; offline HS256/384/512 check against 40 common secrets; then, if the request fails without the token, a changed signature, alg none ×3 and a stripped signature are sent; evidence never contains the token), `graphql` (introspection, batching, field suggestions, the query over GET), `cache_poisoning` (X-Forwarded-Host, X-Host, X-Forwarded-Server, X-Original-Host, X-Forwarded-Scheme, each with its own `pmcb=` cache buster; reported only when the same URL without the header comes back changed), `cache_deception` (private GETs: `/pm<m>.css` and `;pm<m>.css` suffixes, confirmed by fetching them again without credentials), `mass_assignment` (role/isAdmin/is_admin/admin/verified added to JSON or form submissions; reported when the response shows them set) and `proto_pollution` (`__proto__` and `constructor.prototype` with a marker property; reported when it comes back as an ordinary property). Host header probes now also carry a cache buster. VulnShop sits behind a small shared cache (`VulnShop::cached`: static extensions plus `/api/banner` and `/api/notice`, keyed on the target, 30 s) and gains VS-27…VS-32 with traps `/api/notice`, `/api/account/keys`, `POST /api/signup`. Login responses carry a `jwt`.
- **Active scanner, step 4b:** `oauth` (redirect_uri swapped for another site, the registered host as a prefix or user info; then the request without `state`), `deserialization` (Java, PHP, pickle, .NET, Ruby objects found in the *unredacted* request; a corrupted copy must produce a deserializer error), and three checks that raise the gate to the **destructive tier** (`pm_scan::active::APPROVAL_CHECKS`: humans approve, agents are denied by default): `request_smuggling` (TE.CL and CL.TE probes sent byte-exact without Content-Length fixing, against a consistent control; hung = baseline + 4 s, twice), `file_upload` (multipart file part replaced by HTML, SVG and a harmless PHP echo; fetched back from URLs in the response or common folders) and `race_condition` (10 copies through `race_execute`, sent *before* the baseline because the baseline would use up a one-time action; reported when several copies get the recorded 2xx but the request sent alone afterwards doesn't). The sweep runs the approval checks in a second pass only when the ROE allows the destructive tier without asking (`bench/run.sh` does, for its throwaway apps); the crawl-and-audit task leaves them out unless named. VulnShop VS-34 (`/legacy` TE.CL front end), VS-35 (`/oauth/authorize`), VS-36 (`/api/cart` PHP-serialized cookie), VS-37 (`/api/avatar` → `/uploads/`), trap `/oauth2/authorize`.
- **History queries** (`pm_tools::hql`, `q` on `/api/v1/exchanges`, HAR export and MCP `history_search`): `field:value` terms, `field~regex`, OR, `-`, parentheses; numbers take `>N`, `N..M`, `4xx`. Metadata terms run first; request/response bytes load only when a term needs them, and a page stops after 1.5 s with `scanned` and `next_before_id` to continue. Saved filters live in UI state `history-filters`. Measured on 100k exchanges (`crates/pm-service/tests/scale.rs`, ignored; debug build): metadata queries 20–430 ms, content ~5k exchanges/s.
- **History at scale:** the exchange API takes `?max=` (UI asks for 1 MB, "Show all" for the rest; hex shows the first 256 KB); live updates jump to the newest page instead of leaving a gap and keep at most 20 000 rows; "record only in-scope traffic" (`/api/v1/history/recording`, Proxy setup) filters in the proxy's `Recorder`. Store writes use `BEGIN IMMEDIATE`: deferred transactions lost exchanges with SQLITE_BUSY_SNAPSHOT when another connection wrote at the same moment.
- **Session handling** (`pm-service/src/session.rs`, setting `session_handling`, `/api/v1/session`, Settings → Sessions): a cookie jar built from recorded responses (not identity traffic), macros (request steps with regex/JSON/header/cookie extraction into `{{variables}}`), and rules by tool and host that put jar cookies in, set headers/cookies/existing parameters, and run a macro before every request or when a response looks logged out (then send once more; concurrent sends share one run). Applies in `send_now` to requests without an identity; macro steps are gated as the human who saved the rules and recorded as source `macro`. Humans only (macros hold passwords).
- **Manual tools:** intercept queue (requests, responses, WebSocket messages), match-and-replace rules, Replay (send as any identity), race testing (HTTP/2 single-packet attack, last-byte fallback), WebSocket logging/replay/intercept.
- **Safety:** ROE with bypass-resistant scope, tiers per actor kind, rate limits, DNS-rebinding check, single-use parameter-bound approvals, blake3 hash-chained audit log.
- **Plugin platform, part 1 (2026-11-03; ADR-0015)** (`pm-plugin/src/{active,sandbox}.rs`, `pm-service/src/plugins.rs`, Utilities → Plugins, `/api/v1/plugins` (+ `/check`, `PUT /{name}`), `proxymind plugin list|enable|disable|check`, MCP `plugin_list`/`plugin_check`, SDK `plugins`/`plugin_check`): active-check plugins (manifest `active:` with `max_requests`) run twice per check (`probe` → origin-form requests to the exchange's host; `judge` → issues). The batch is gated once as `plugin_check` (≥ intrusive); a pending approval stores the requests and running with its id sends exactly those. Sends use `send_as` (per-request scope, limits, identities; history source `plugin`). Every plugin process (passive too) runs with a cleared env and, on Linux, `unshare --user --net` + `prlimit` when available (`sandbox::status()`; `PROXYMIND_PLUGIN_SANDBOX=off` disables it for debugging). The service reads the user's registry on use (`attach_plugin_home`). Example: `examples/plugins/debug-switch` finds VS-22. Tests: `pm-service/tests/plugins.rs`, sandbox unit tests, e2e Plugins step. Python authors can use `proxymind.plugin` (`run(probe=…, judge=…, passive=…)`, `with_query`, `set_header`; stdlib only). Not done: plugin UI panels (sandboxed iframes), a WASM runtime, signed manifests, a TypeScript helper.
- **Proxy streaming and connection reuse (2026-11-04):** responses stream to the browser (`Sender::send_start`/`send_h2_start`, `Conn::body_chunk`, HTTP/2 data within the browser's flow-control window) unless a response rule or the intercept queue needs the whole message (`Proxy::buffers_response`); history keeps the first `RECORD_CAP` (64 MB) with a note. Head and body-idle timeouts are 300 s. The proxy answers `Expect: 100-continue` itself. TLS EOF without close_notify ends a stream; HTTP/2 `RST_STREAM NO_ERROR` after a response is a normal end. Server connections are reused (`pm-replay/src/pool.rs`: HTTP/1.1 kept 30 s, 6 per host, reused for GET/HEAD/OPTIONS with a retry if the kept one is dead; one shared HTTP/2 connection per host); Replay, scans and fuzzing still open one connection per request. Checks: `bench/proxy/run.sh` (30 traffic cases), `bench/proxy/soak.sh` (real browser), `bench/proxy/load.py`; tests in `pm-proxy/tests/streaming.rs`.
- **Naming (2026-10-28):** ProxyMind's own names for its tools: Replay, Fuzzer (modes: one at a time, same everywhere, paired, all combinations; Auto-mark), Codec, Diff, Token analyzer. Names used before (repeater, intruder, sequencer) still match in saved session rules, and Replay reads tabs saved under the old `ui:repeater` key.
- **Hardening pass (2026-10-27):** API tokens are 32 OS-random bytes with a `pm2_` prefix (older token files are replaced) and OAST tokens use OS randomness; the payload classifier treats `X-HTTP-Method-Override`, `X-HTTP-Method`, `X-Method-Override` and `_method` as the real method; plain HTTP through an HTTP upstream proxy always names the checked endpoint (absolute-form targets are rewritten, CONNECT/`*` refused); one buffered message is capped at 256 MB (`pm_replay::MAX_MESSAGE`); OAST callbacks are capped (20 per token, 100k total) and looked up by token; the OAST HTTP listener allows 10 s per request head; the CA keeps at most 10k leaf configs; identity credentials, session-rule values and values extracted at login or by macros never carry CR/LF/NUL into requests; cURL `-G` data, OpenAPI example requests and chunked decoding were fixed after fuzzing; new project files and unlocked copies are mode 0600; a due schedule is claimed in the database (`Store::claim_schedule`) so it fires once across processes; the proxy warns when it listens beyond loopback. Second pass: approvals are bound to the requesting actor and action and have random ids; every MCP/assistant tool result goes through `Service::json_for` (agents: secrets redacted, `evidence` tagged untrusted); `transmit` checks each request's own path against scope (payloads can't walk into excluded paths) and records refused ones without sending; agents can't change status/severity/description of findings that aren't `suspected`; workflow actions are pinned to SHAs with Dependabot; the desktop lockfile is audited in CI (`desktop/deny.toml`); the audit chain can't show records cut off the end by itself, so `audit verify` prints the head hash, reports include it, and `audit verify --anchor <hash>` fails if that record is gone.

```bash
cargo build
```

### Patterns to follow when adding a feature
1. Pure logic in the lowest crate that fits (parsers and verdicts sans-I/O, with unit tests).
2. A `pm-service` method that gates the action (`gate_send_with`, choosing the tier; approvals must cover every parameter that changes what is sent) and records what was sent.
3. Expose it in `pm-mcp/src/tools.rs` (description written for a model, `deny_unknown_fields` arg structs), `pm-api/src/routes.rs`, and the UI. Update `docs/agents.md` when tools change.
4. Integration tests against VulnShop or small local servers in `tests/`, and a step in `ui/tests/e2e.mjs` for UI work.
5. Update `docs/plan.md` (Status / Next) and the README; add an ADR for hard-to-reverse decisions.

### Environment pitfalls seen in the cloud sandbox
- **Disk fills up.** `target/` grew past 30 GB, and a full disk shows up as `ld … Bus error`. Build with `CARGO_INCREMENTAL=0`, and run `cargo clean` if space runs low.
- **Chromium** is preinstalled at `/opt/pw-browsers`; never run `playwright install`. The e2e HTTP/2 step needs `openssl` on PATH.
- **`localhost` resolves to IPv4 only in the sandbox** but to `::1` first on CI runners. Tests that use `localhost` must work with both (this caused a CI-only failure once).
- **The UI e2e Intercept step (`held-drop`) timed out once locally** and passed on reruns; watch for it in CI.
- **Windows CI is the slowest job** (≈7 min). Keep timing assertions generous and prove ordering instead of tight durations.
- **No `gh` CLI.** Use the GitHub MCP tools (load them with ToolSearch) for PRs and CI logs.
- **Git:** develop on the branch the session assigns. Commit messages end with the attribution trailers from the session's instructions. Don't put model identifiers in repo files. Open PRs only when asked. `main` gets merges of PRs (merge commits).
