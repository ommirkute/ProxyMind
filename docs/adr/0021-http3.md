# ADR-0021: HTTP/3 as text, sent over QUIC with quinn and h3

**Status:** Accepted

## Context
Roadmap 2.4 asks for HTTP/3. Two facts shape what it can mean here.

- **Browsers do not use HTTP/3 through an HTTP or SOCKS5 proxy.** CONNECT carries TCP, QUIC is UDP, and browsers fall
  back to HTTP/2 or HTTP/1.1 for proxied traffic. So an HTTP/3 *listener* is not needed for the normal "browser, then
  ProxyMind" setup: the browser never offers it.
- HTTP/3 still matters in two ways. (a) Targets that serve HTTP/3, and sometimes behave differently over it (another
  front end, other header handling, other WAF rules), have to be testable: Replay, the Fuzzer, the scanner and agents
  need to send over HTTP/3. (b) In transparent and invisible setups (ADR-0003's CA, `docs/capture.md`), a client that
  learned `Alt-Svc: h3=":443"` from an intercepted response opens a QUIC connection to the target next time. If UDP
  reaches the target, that traffic goes around ProxyMind. Interception must not be bypassable by accident.

ADR-0009 settled how a multiplexed protocol is shown: as HTTP/1-style text, so every tool works on it unchanged.
ADR-0003 settled the TLS backend: rustls with the `ring` provider, no C toolchain. ADR-0002 keeps bytes unchanged
unless a user or rule asked.

## Decision

### Stack: `quinn` + `h3` + `h3-quinn` on rustls (ring)
| Crate | Version | License | Role |
| --- | --- | --- | --- |
| `quinn` | 0.11.12 (`quinn-proto` 0.11.19, `quinn-udp` 0.5.16) | MIT OR Apache-2.0 | QUIC transport |
| `h3` | 0.0.8 | MIT | HTTP/3 and QPACK |
| `h3-quinn` | 0.0.10 | MIT | glue between the two |

- They use the **rustls 0.23.46 and the `ring` provider that the workspace already has** (quinn features
  `runtime-tokio`, `rustls-ring`, `log`; default features, which add the platform verifier, are off). `Cargo.lock`
  gains 18 packages, all licensed MIT or Apache-2.0 (some with Zlib), all on `deny.toml`'s allow-list; nothing needed a
  new allowed license, and no existing crate changed version. No C or C++ code, no cmake: ADR-0003's contributor
  setup is unchanged.
- The dependencies live in `pm-replay` only (the send engine). `pm-http` stays free of I/O and of these crates;
  `pm-proxy` does not depend on them.
- Cost: see "Consequences" for binary size and build time.

Alternatives looked at:
- **`s2n-quic` (+ `s2n-quic-h3`)**: Apache-2.0, solid, but brings its own TLS provider or a second rustls path, a
  larger dependency tree, and the same `h3` crate on top. No gain over quinn for this use.
- **`quiche` (Cloudflare)**: BSD-2-Clause, fast, but needs BoringSSL (C, cmake, a C toolchain): the cost ADR-0003 avoided.
- **`neqo` (Mozilla)**: MPL-2.0 and NSS, a C dependency; **MsQuic** bindings: C as well.
- **Our own HTTP/3 framing over quinn** (skip the `h3` crate): would allow frame-level control (single-packet sends,
  malformed frames) but is a large piece of work for no user-visible gain now. Deferred; the text form can't express it
  anyway (like ADR-0009 for HTTP/2).

Risks: `h3` and `h3-quinn` are 0.0.x crates, so their API can change in any release. `Cargo.toml` names the versions,
`Cargo.lock` pins them, and the code that uses them is one file (`pm-replay/src/h3send.rs`) plus the test server.

### HTTP/3 as text (follows ADR-0009)
- An HTTP/3 request is shown, edited, stored and searched as HTTP/1-style text with **`HTTP/3`** as the version and
  `host:` standing for `:authority`; header names are lower-case, connection-specific headers are not used, and
  `:scheme` comes from the target (always `https`). It is the same shape as the HTTP/2 form, and it is read and
  written by the same code (`pm_http::h3text`, on top of `h2text`), so rules, intercept, Replay's editor and Inspector
  (pseudo-headers), identities, authz checks, redaction, search, the scanner and the Fuzzer work on it unchanged.
- A response is stored as `HTTP/3 200` followed by the headers and the body; trailers appear after the headers. Tools
  that need HTTP/1.1 text (the browser render view, proofs, passive checks) convert it like HTTP/2 text
  (`to_http1_response`).
- **A request whose request line says `HTTP/3` is sent over HTTP/3. Nothing else switches protocol.** There is no
  automatic upgrade, no Alt-Svc cache, no "try HTTP/3 first". The scanner, the Fuzzer and workflows send what the
  request text says. Replay's protocol selector writes the version into the request line.
- What the text form cannot express, as for HTTP/2: QPACK encoding, frame boundaries and order, duplicate-name header
  order across names, GREASE, 0-RTT, connection migration, datagrams and WebTransport. Frame-level tooling is a later,
  separate piece of work.
- ADR-0002 is not touched: HTTP/1.x bytes are never converted to or from HTTP/3 text unless a user, rule or the
  request line asks for it.

### Scope of this work package
1. **Upstream client** (`Sender::send` in `pm-replay`, `h3send.rs`): `HTTP/3` text over QUIC to an `https` target.
   - *DNS rebinding:* the host is resolved in ProxyMind (or taken from a host override or a transparent-mode pin), the
     list of addresses goes to the caller's check (the policy gate's denied networks), and the UDP sockets connect to
     exactly those addresses (up to four tried at once: UDP gives no refusal, so a dead IPv6 address must not delay a
     working IPv4 one). The server name for TLS is the host name, never the address.
   - *TLS:* the same verification setting as every other send (`--verify-upstream`, per-host client certificates),
     ALPN `h3`, TLS 1.3 as QUIC requires.
   - *Limits:* the connect timeout covers DNS and the QUIC handshake, the read timeout the whole exchange; response
     bodies are limited to 64 MB (as HTTP/2), then the send fails.
   - *Upstream proxy rules:* HTTP and SOCKS5 proxies carry TCP only. If an upstream rule routes the host through a
     proxy, the send is **refused** with an error that says why and what to change (use HTTP/1.1 or HTTP/2, or make the
     rule for this host `direct`). It never goes direct behind the rule's back. A `direct` rule, or no rule, sends over
     QUIC. A plain `http` target is refused too (QUIC always uses TLS).
   - One connection per send (no pool, no 0-RTT). Streaming sends (`send_start`), race and parallel sends and replay
     groups in parallel mode refuse HTTP/3 text with a clear error rather than sending it as another protocol.
2. **History:** exchanges are recorded with the HTTP/3 text form (request and response), so History, search, the
   Inspector, exports, the scanner and agents see them like any other. History's detail view shows a protocol label.
3. **Alt-Svc:** (a) a response that advertises `h3` or an `h3-NN` draft in `Alt-Svc` gets an **"offers HTTP/3"** chip in
   History and Replay, and **"Send with HTTP/3"** (History opens Replay with the request written for HTTP/3 at the
   advertised host and port; Replay sends the shown request again over HTTP/3). (b) The match-and-replace preset
   **"Remove HTTP/3 advertisements (Alt-Svc h3)"** in `pm_proxy::presets`. It is a person's opt-in like the other
   response presets, off by default, for in-scope hosts, and it only drops the `h3`/`h3-NN` alternatives (other
   alternatives stay; a header left empty is removed). The record keeps the server's original response next to the
   delivered copy (the mechanism ADR-0020 step 1 added), so History still shows what the server offered.
4. **Client-side QUIC listener: deferred** (below).
5. **API and UI:** no new endpoint. `replay_send` and `POST /replay` take the protocol from the request line, so the
   REST API, MCP, SDKs and CLI get HTTP/3 without a new field; the schema texts say so. UI: Replay's Protocol selector
   (HTTP/3 beside HTTP/2 and HTTP/1.1) and pseudo-header Inspector, protocol and "offers HTTP/3" labels in History,
   and the preset on the Rules page.

### Deferred
- **A QUIC listener for clients** (transparent mode terminating QUIC with the ProxyMind CA, forwarding upstream as
  HTTP/3). It is a work package of its own, because it needs: a UDP socket that learns each datagram's original
  destination (`IP_ORIGDSTADDR` through TPROXY on Linux; quinn's socket abstraction does not expose it, so a custom
  `AsyncUdpSocket` and `nix` calls, still without `unsafe`); a per-SNI certificate resolver from `CertAuthority` with
  ALPN `h3` and TLS 1.3; an HTTP/3 server module next to `h2_server.rs` that turns each stream into HTTP/3 text and
  runs the same rules, intercept queue, hooks and recorder; loop protection and connection-migration rules; firewall
  documentation for UDP redirection; and macOS and Windows have no transparent UDP at all. Until then the answer to
  "don't let HTTP/3 bypass interception" is the Alt-Svc preset above plus **blocking UDP/443 at the firewall** so
  clients fall back to TCP (`docs/capture.md` shows the rule). Clients that already hold a cached alternative keep
  using it until it expires (`ma`), so the block matters more than the preset.
- HTTP/3 over HTTP-proxy CONNECT-UDP (MASQUE, RFC 9298) for upstream proxies that support it.
- HTTP/3 in race and parallel sends (QUIC can put several streams' final packets together; the same idea as the
  HTTP/2 single-packet attack), streaming responses to clients, a connection pool, 0-RTT.
- WebSockets over HTTP/3 (RFC 9220), WebTransport, datagrams, Alt-Svc caching or automatic upgrade (by design: never
  without a request that says so), QUIC client fingerprint control (like the JA3/JA4 note in ADR-0003), frame-level
  tooling.

## Consequences
- Replay, the Fuzzer, the scanner, workflows and agents can test HTTP/3 targets today, with the same gate, identities,
  rate limits and audit as any send.
- The proxy path for HTTP/1.1 and HTTP/2 does not change when HTTP/3 is not used: the only edit there is a check of the
  request line (`HTTP/3`) next to the existing `HTTP/2` check, and nothing starts a QUIC endpoint until a request asks
  for one. The Phase 1 benchmark is not affected (nothing runs on its path; only the binary is larger).
- Binary size and build time grow (numbers below). `cargo-deny` and the license allow-list pass unchanged.
- The text form hides what only frame-level tooling shows, and `h3`'s 0.0.x API may need adapting when it releases.
- A client that does not use the proxy setting can still reach a target over QUIC unless UDP/443 is blocked; the
  preset and the firewall rule reduce that, and the deferred listener closes it.

### Measured cost
Release build of `proxymind` (`cargo build --release -p pm-cli`, thin LTO, same machine): 45,883,536 bytes before,
48,559,224 bytes after: **+2.7 MB (+5.8%)**. A clean release build took 6 minutes both times (the new crates compile
in parallel with the rest). A debug build of `pm-replay` and its dependencies adds about 50 seconds from clean.
